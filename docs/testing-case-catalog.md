# CoworkOS 五个环节的测试用例目录

按 **基础功能 → CLI 专门功能 → App 功能 → App 内应用功能 → 用户 case** 阅读和维护。每个环节先列功能，再列操作与通过标准。发版前本地运行本套验收，不新增 GitHub CI。单元、集成、真实引擎、真实模型、优先级和本地发布批次统一作为执行属性，详见 [执行与发布规则](testing-execution-guide.md)。

这是待逐项映射和实现的测试清单。现有测试锚点供复用，不表示全部断言已经覆盖。CLI 与 App 的基础机制只在第一环节定义，后续环节验证各自入口是否正确使用它们。共享资源及软件契约归第四环节，CLI 有对应无界面入口时复用同一契约。

使用 `npm run test:release -- --list` 查看本地执行分组；映射见 `test/release/catalog.json`。已有测试文件仅是部分覆盖线索，逐项通过需核对当前断言，不引用历史通过计数。

| 环节              | 验证对象                         | 验收结果                        |
| ----------------- | -------------------------------- | ------------------------------- |
| 一 基础功能       | 不依赖终端或界面的 harness 核心  | 每个核心机制行为正确            |
| 二 CLI 专门功能   | 终端入口、配置、安装、命令和交互 | 核心能力经 CLI 可用             |
| 三 App 功能       | 桌面宿主、会话界面、输入和导航   | 核心能力经 App 可用             |
| 四 App 内应用功能 | 工作台、TXT、外部软件操作        | 用户与 Agent 能正确协作操作应用 |
| 五 用户 case      | 一个完整用户目标                 | 多项能力组合后能交付正确结果    |

## 一 基础功能测试

通过函数、服务接口和真实运行进程测试共享核心。此环节不要求点击 App 控件或操作终端 UI；界面呈现与终端交互分别进入第三、第二环节。

### 3 Task 和 Run 状态

| ID     | 检查场景                                                                       | 通过标准                                                                          |
| ------ | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| RUN-01 | 创建、开始、完成、失败、等待、取消及非法转移                                   | 状态和事件一致；非法转移拒绝；Task/Run 身份关系可重读                             |
| RUN-02 | 同 Task 双启动、start/stop 交错、两 Task 并发、旧请求迟到                      | 同 Task 无重复 active 进程；不同 Task 隔离；旧 Run 不改新状态                     |
| RUN-03 | 旧 session 末尾 error/aborted/stop，新进程零输出/启动失败                      | 本次终态只消费本次证据，不能套用旧消息；失败只落盘一次                            |
| RUN-04 | finish_task 后 SSE 错误、取消、关机，以及正常 explicit finish                  | 完成声明与最终实际结果一致；受控恢复只作用于当前 activeRunId；历史 Run 不被误重开 |
| RUN-05 | 落盘后崩溃、退出前中断、重启继续、预算到期                                     | 重启能核对真实进度；保留部分文本/成功工具；不误报 completed，不丢已提交数据       |
| RUN-06 | natural/explicit 完成策略、required/independent 子任务、partial 结果、人工等待 | 完成前置条件符合策略；必要任务/问题未结束不能 completed；独立工作按明确合同收尾   |

## 五 具体用户 case 测试

从用户输入一个目标开始，经过实际执行，最后独立检查交付结果。前四环节验证局部功能，此环节验证能力组合。前 8 项与 CASE-17 至 CASE-21 在 CLI 与 App 分别运行；后续应用任务按入口和依赖选择执行。

前 8 项是两端共享核心集。每项建立两个独立变体：**fixture + 真实执行工具**用于确定性回归；**真实模型自由规划 + 同一 oracle**用于能力评测。App 变体通过输入框提交并从 UI 查找产物；CLI 变体使用已安装命令。涉及主动委派的 case 在任务说明明确要求 Main 使用 Subagent，否则不能把模型选择不委派误当委派功能失败。

| ID      | 用户任务和固定输入                                           | 独立成功标准                                                                  |
| ------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| CASE-01 | 创建 hello.txt 写入中文/Emoji，读回确认并交付                | 成品 UTF-8 内容精确符合任务，真实路径/hash 正确，UI/CLI 可取回                |
| CASE-02 | 修复小项目的计算 bug，保持测试不变并运行测试                 | 隐藏测试通过，原测试 hash 不变，允许路径之外无变更；最终代码独立运行          |
| CASE-03 | CSV 包含 10/20/30，另有缺失值及 Unicode 字段，按指定规则统计 | total=60、缺失值规则正确；报告与结构化数据一致且独立解析                      |
| CASE-04 | 明确要求两个异步 Subagent 分析两个局部数据，再由 Main 汇总   | 两个不同委派真实执行、持久回调消费、汇总数值正确；无未结束队列/重复副作用     |
| CASE-05 | 输出方案前先请求用户选择 A/B，回答 B 后继续                  | 等待期间不执行；实际结果采用 B；问题/草稿跨重启仍正确                         |
| CASE-06 | 创建第一步 marker 后运行可控慢任务，用户取消再继续           | 取消进程退出；继续核对已完成步骤；marker 一次；最终产物正确且 Task 原身份     |
| CASE-07 | 第一轮成功工具后模型流中断，界面/CLI人工继续                 | 已知副作用一次；部分信息保留；未发送草稿/附件不被重试消费；最终独立验收       |
| CASE-08 | 在项目外生成文件，用 publish_artifact 发布并下载             | 外部源不丢；当前 Task 索引/最终路径/下载字节一致；缺源不误报交付              |
| CASE-09 | TXT 多轮协作：用户先改一段，Agent 按选区修改，再制造冲突     | 合并范围正确；冲突不丢草稿；撤销生成新版本；重启可恢复                        |
| CASE-12 | 经人工授权观察隔离窗口，输入中文/Emoji/多行，点击保存，接管  | 目标控件/保存文件读回正确，权限归属准确；接管后零动作；真实视觉模型可核对反馈 |
| CASE-13 | 根据合成资料生成 PDF/DOCX，指定页数/关键数字/表格            | 独立解析+渲染核验内容和布局；可打开，关键值准确；错误产物不报完成             |

| CASE-23 | 用户问题等待中 Stop，再启动同 Task 新回合；旧答案/旧页面 Stop 迟到              | 新回合不受旧请求影响；旧问题状态真实；仅当前明确提交的要求执行，最终产物和两端显示符合新目标               |

CASE-09 为 App 重点、CLI 无界面资源编辑为辅助变体；CASE-12 需 Mac App 人工权限；CASE-13 需对应 Skill/文档依赖。依赖未满足时执行其缺依赖诊断用例，原成功 case 标 BLOCKED。CASE-14/16 有研究及长程属性，首版不必与基础 CLI 主链路共用一次发布成功率。

### 新功能如何补充用例

先确定它属于前四个环节中的哪一个，增加功能测试；若新增了用户可完成的目标，再在第五环节加入完整 case。每个用例记录前置条件、步骤、通过标准、依赖和实现位置，使用 [统一模板](testing-case-template.json)。故障、取消、并发和权限变体附在对应功能下，不另建一套功能分类。
