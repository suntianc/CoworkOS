# 代码地图与修改入口

[English](en/code-map.md) | 中文

开发 Agent 先读根目录 [AGENTS.md](../AGENTS.md) 和目标目录的 `AGENTS.md`，再用本页选择负责行为的模块和测试。职责与依赖见 [架构](architecture.md)，执行命令见 [开发指南](development.md)。

品牌入口：界面显示名在 [产品名](../desktop/product-name.cjs)，桌面运行与打包身份在 [profile](../desktop/profile.cjs)，安装包名在 [打包配置](../electron-builder.config.cjs)，CLI 命令与兼容别名在 [package](../package.json) 和 [CLI 打包](../scripts/package-cli.mjs)，会话身份在 [agent identity](../src/domain/agent-identity.ts)。CoworkOS 的旧数据、钥匙串、协议与更新兼容规则见 [安装参考](installation-reference.md#名称与旧版兼容)。

README 头图由 [独立 React/SVG 工程](hero/README.md)生成：`scene.jsx` 负责构图，`TechText.jsx` 负责字形与固定 OS 选框，`HarnessCorner.jsx` 绘制应用局部；渲染与编码生成 `docs/assets/readme-hero.gif` 和静态 PNG。

## 目录地图

```text
scripts/install.sh         CLI 安装：公开发行版、下载校验、用户目录与 PATH
scripts/atria.mjs          用户 CLI 启动器：init、doctor、start 等命令
src/cli/                  可执行入口和真实模型 smoke
src/domain/               Task、Run、Watch、Experiment、Virtual Agent 类型
src/runtime/              Pi 会话、委派、恢复、Inbox、checkpoint、长期运行
src/tools/                文件、命令/jobs、Web 等运行时工具
src/workspace/            Task 工作区、附件、产出物、项目与全局会话索引
src/storage/              JSONL 事件、trace、文件锁
src/dashboard/            本机 HTTP/SSE、路由、服务装配、Main 进程生命周期
src/applications/         应用注册、实例、资源、revision、绑定、Adapter、MCP
src/software/             通用软件驱动与异步软件协议
src/gui/ + src/security/   Computer Use、原生驱动、执行权限
.pi/extensions/           Pi 薄入口
.pi/runtime/              Pi 生命周期装配、应用桥接、分领域工具
.pi/skills/               随产品交付的技能与参考资料
web/                      原生 ES modules：页面装配、控制器、工作台、领域 UI
desktop/                  Electron 主进程、可信 preload、模型加密、退出保存
test/                     Node 行为/协议/生命周期回归；p0/p1/p2 为编译后测试
e2e/                      Chromium 与独立 Electron 用户流程
scripts/                  构建、打包、开发启动、测试与文档检查
docs/                     用户指南、开发约定与接口参考
```

CLI 一条命令安装由 [install.sh](../scripts/install.sh) 负责，使用公开更新清单、校验后的发行包和用户目录。安装与拒绝路径见 [安装回归](../test/install.test.js)，运行 `node --test test/install.test.js`。

`src/cli/` 不存放可复用的 HTTP 或 MCP 业务实现。HTTP 帮助函数在 `src/dashboard/`，MCP HTTP 客户端在 `src/applications/mcp/local-api-client.ts`。构建输出在 `dist/`、`build/`、领域 UI 的 `generated/` 和 `.tmp/`；从源文件修改后重新构建。`build/` 中的桌面图标由 [图标构建脚本](../scripts/build-desktop-icon.mjs) 从 [原始标志](../web/assets/atria-symbol.png) 和 [Swift 渲染器](../scripts/render-desktop-icon.swift) 生成，供开发 App 和打包使用，不手工维护或提交生成副本。

工作与观测两个入口的状态由 [入口控制器](../web/assets/controllers/entry-controller.js) 持有：入口、观测视图与刷新后的恢复都经它读写，`web/index.html` 里带 `data-entry-panel`、`data-entry-mode`、`data-observe-view` 的元素是 #03、#09 起各票的挂载点。验收为 [入口控制器回归](../test/p45-entry-shell.test.js) 与[浏览器切换](../e2e/p45-entry-shell.spec.js)。

观测的只读数据由[观测数据端口](../web/assets/controllers/observe-data.js)统一提供：每个已连接节点各持一份会话、目录快照与事件流，按节点汇总项目、需求计数与运行数；本机节点复用页面现有的管理客户端，不另开事件通道。侧栏由[观测侧栏控制器](../web/assets/controllers/observe-sidebar.js)渲染视图计数、节点与项目，选择写入 `#observe-entry` 的 `data-observe-node`/`data-observe-project`，视图只读端口而不持有连接。设置的节点连接页经同一端口添加、重命名、重新授权、重连、断开与移除节点，节点记录和每个 origin 的令牌分开保存，一个节点失败不影响其他节点。验收为[多节点端口](../test/p45-multi-node-client.test.js)与[两个本机后端实例](../e2e/p45-multi-node.spec.js)。观测需求视图由[观测需求控制器](../web/assets/controllers/observe-requirements.js)渲染：列表按阶段分页签计数并按节点、项目与搜索筛选，详情只读同一需求的处理会话、归属、合入、台账版本、完成标准、审查结论与改动统计；阶段与分页签归类来自[阶段映射](../web/assets/requirement-stages.js)，每个需求的交付视图与项目的主会话、看板都经端口按 origin 读取，观测不提供打开会话或查看 diff。端口给每次节点请求统一附带只读标记，被观测节点的补投留在它自己身上而不由观测触发。验收为[阶段映射组合](../test/p45-requirement-stage-mapping.test.js)、[只读读取](../test/p45-observe-readonly-reads.test.js)、[跨节点列表与筛选](../e2e/p45-observe-requirements.spec.js)、[需求详情](../e2e/p45-observe-requirement-detail.spec.js)与[观测只读](../e2e/p45-observe-readonly.spec.js)。
运行视图由[运行泳道控制器](../web/assets/controllers/observe-runs.js)渲染：按节点读 Main 会话与运行中的 Task，从 `task.activity` 画阶段波形、子 Agent 分支与无进展标记，对外节点按常驻/接续名额分组并留出空名额平线；节点不提供活动指标时改画阶段色块并显示"指标未就绪"，减少动态效果时改为固定间隔的静态快照。验收为[泳道控制器回归](../test/p45-pulse-lanes.test.js)、[两个节点下的泳道](../e2e/p45-pulse-lanes.spec.js)与[指标未就绪/减少动态效果](../e2e/p45-pulse-lanes-degraded.spec.js)。
观测总览由[观测总览控制器](../web/assets/controllers/observe-overview.js)渲染：节点卡片按节点角色显示运行中、等待你、本周合入，或对外节点的常驻/接续名额与待认领，离线节点只显示最后在线；需求矩阵把各项目需求按设计稿的五列归类（阶段来自[阶段映射](../web/assets/requirement-stages.js)），"需要处理"只读列出等待回复、审查未通过、长期待认领与节点离线，"正在运行"读需求、项目、节点、Main 会话、阶段与时长。项目记录以只读列表读取（看板、会话、开发、审查、合入、交付），不触发补投或 git 计算，只在视图可见时刷新。验收为[总览控制器回归](../test/p45-observe-overview.test.js)、[跨节点总览](../e2e/p45-observe-overview.spec.js)与[需要处理](../e2e/p45-observe-attention.spec.js)。

## 三种常见修改流程

### 修复一个用户流程

从复现对应的 `e2e/` 或协议测试进入，沿请求或事件找到状态负责人。在负责人中修复语义，路由只调整字段/状态码映射，UI 只调整展示/交互。补一个能复现原失败的回归，再运行本页相关测试和 `npm run verify`；改变 UI 还运行相应浏览器用例。

### 接入一个新应用或工具

先确定资源格式、revision、取消和失败保证，再实现 Adapter/软件驱动、能力发现和领域工具；最后接工作台注册与 UI。共享协议归 `applications/types.ts` 或 `software/contracts.ts`，HTTP/Agent/UI 共用同一操作语义。遵循 [软件接入流程](software-integration.md)，验证 Agent 首轮发现、人工与 Agent 并行写入、冲突保留草稿和保存重开。

### 拆分一个大模块

先识别纯状态转换、存储、进程所有权和展示各自负责的行为，保持现有导出/数据格式/入口不变，一次迁移一个职责并更新消费者。新增模块不反向导入装配层；用 [边界回归](../test/architecture-boundaries.test.js) 和原行为测试验证。验收应检查依赖方向和恢复行为。

职责主责角色见 [所有权表](module-ownership.md)。根目录与各目录的 `AGENTS.md` 是修改约束；本页提供功能与测试的查找线索。
