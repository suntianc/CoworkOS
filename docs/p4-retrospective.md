## 阶段内修复与经验

### 1. 共享记录与执行现场分别核对

#01 的 Remote 创建最初误走 authority 的 owner 校验，部分列表、查询和更新又使用 authority 的现场归属。状态写入失败后，完整 checkout 也无法恢复。修复后由 authority 保存共享事实、执行主机准备本地 Git，读取按 backend 归属过滤，已创建现场能够对账续接；双后端 SQLite/PostgreSQL 验证通过。

后续修改共享接口时，沿已有交接逐入口核对记录写入、Git 操作和现场读取的负责人。P3 的 admitted-caller/backend attribution 保持既定信任边界，跨租户隔离仍属后续议题。覆盖：[工作区](../test/p4-development-workspace.test.js)、[远端消费者](../test/p4-development-workspace-consumers.test.js)。

### 2. 模型在实际开始时解析，工作项各有 Git 现场

#02 初版在依赖等待前固定模型；恢复解析失败被过滤后可能一直 pending；并行工作项共用 checkout，测试甚至断言路径相同。按原规格修复后，模型在实际启动时解析，在途快照保持不变；失败进入可定位终态，拒绝启动保护身份和实验归属；每个工作项拥有独立现场，续接复用原现场。

测试需验证用户可观察的语义，例如等待期间配置改变后的选模、并行写入的目录隔离。原并行容量超时只保留了日志片段，后续独立及组合检查通过，首失败根因仍未确认。覆盖：[原生执行](../test/p4-native-execution.test.js)、[角色生命周期](../test/p4-native-role-lifecycle.test.js)。

### 3. 审查发现需要跨失败和多轮返修保持来源

#03 的 failed/drifted 审查发现无法裁定，返修只结算直接前任，Reviewer 身份能够覆盖，Quick 旧检查可被当作新 HEAD 的批准。Main 使用真实 Git、SQLite 和生产服务的短探针复现，并纠正了一个无效 callId 导致的错误推断。

修复覆盖固定 Reviewer 身份、失败后的裁定、显式祖先发现结算，以及当前候选自检资格。后续审查应检查版本和状态转换的完整链路。覆盖：[候选审查](../test/p4-candidate-review.test.js)、[发现裁定](../test/p4-review-decisions.test.js)。

### 4. 合入与交付记录绑定实际 Git 事实

#04 验证了项目级串行目标更新、配置 writer 与各后端 checkout 的分离、目标前移后的组合检查，以及已合入祖先的崩溃恢复。#05 随后修复了回执字段核对不完整、同步时间被当作合入时间、恢复依赖读取触发，以及交付 diff 随活动 HEAD 改变的问题。

最终交付保存完整 canonical receipt 和实际合入时间；宿主可停止的恢复任务自动补写共享记录，本地 Run 独立收尾；交付 diff 固定在已合入版本。已认领看板需求更新为待发布及实际 commit。覆盖：[项目合入](../test/p4-project-integration.test.js)、[Git 恢复](../test/p4-integration-recovery.test.js)、[交付记录](../test/p4-delivery-records.test.js)、[消费者](../test/p4-delivery-consumers.test.js)。轮询重构、outbox 容量等建议尚未实施。

### 5. 产品模型配置是独立的验收前置

#06 外部执行 CLI 可用时，OS 自身仍为 `configured=false`。等待产品配置期间，Main 完成同包双引擎补证与报告元数据修正；配置完成后核对已有 Task/Run，保留取消的首轮尝试，由原执行者续接。

这个触发条件已整理为 [产品模型配置坑点](pitfalls/testing.md#真实模型验收前产品连接未配置)。模型凭据留在产品配置，档案只保存就绪状态和版本。等待时长没有对应的模型消费统计，复盘不据此估算额度。

### 6. stdin EOF 修复保留宿主生命周期管道

真实链路中的两次 awk 等待暴露了实际命令继承 stdin 的缺陷。#06 集成后，Main 在已接受提交上有界复现，再以新票 #07、新执行上下文修复：实际命令从空设备获得 EOF，owner→host 生命周期管道保持原协议，shell 输入重定向继续有效。

准确的超时含义为：命令默认 30 分钟，显式 `commandTimeoutMs=0` 才无限；子 Agent wall-clock 默认 0 属另一层设置。修复没有增加子 Agent 配额或缩短超时。双语文档、[EOF 回归](../test/foreground-command-stdin.test.js) 及生命周期检查已覆盖；原两次人工介入、取消尝试和红绿证据继续保留。

### 7. 失败逐项归因，复用按源码和输入判断

#06 首次 full 有 11 个失败，基线输入对照确认是本阶段接口变化后的旧断言，修正后全绿。Python、Electron、Chromium 前置以及 PostgreSQL 回执引用分别核对；报告示例 ID 错误按原始回执更正。

部分探针先后遇到夹具权限、短 SHA、inline 引号、返回对象被误当成抛错、Git 输出断言形状错误。原失败和校正结果均保留。后续可先校准探针输入及返回契约，再对固定候选运行；一次性构造错误留在复盘，现有环境坑点继续复用。

终审第一轮的检查全部通过，但报告写成 Markdown 标题和加粗 pass，工具未读到 verdict。第二轮独立核对同 tip 原始回执并补正确字段，复用已完成命令。工具问题集中见 [Workloop 跟进项](workloop-followups.md)。

归档删除 scratch 和执行工作树时，里面仍有用户配置、凭据、交付样例和 Main 管理的 UI。Main 核对实例归属与空闲状态，将同版本源码和数据移入私有持久目录，保留兼容访问并恢复服务；秘密未进入 evidence。用户现场保留原 `613c4d5f` 版本，最终交付包包含后续 stdin 修复。

归档前后的数据、工作树和运行状态均有回执。该触发条件已加入 [归档数据坑点](pitfalls/testing.md#归档目录内仍有用户配置的实例)。后续采用独立持久目录的验收模板、工具占用预检等仍是待评估建议。
