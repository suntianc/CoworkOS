## WL-01 provider 替换与返修计数

科学剪枝发生过一次 README 返修和 Terra → DSH 替换，工具机械 rework 为 0。建议同时呈现替换原因、前轮 verdict、实际返修与工具计数，避免用替换或 retry 隐去返修。当前交接可按 [替换执行者](development-handoffs.md#替换执行者与归档) 记录；工具计数改动另行评估。来源：[科学剪枝复盘](core-pruning-retrospective.md)。

## WL-02 返修简报中的验证责任

科学剪枝的窄文案返修仍引发重复检查。建议通用简报列出本轮增量、执行者检查、独立审查及集成/finish 必需门禁。项目侧已有 [交接表](development-handoffs.md#派发与返修)，通用模板尚未修改。来源：科学剪枝复盘与 [P3 重复准备](p3-retrospective.md#8-减少脚手架试错和重复准备)。

## WL-03 组合参数忽略交接正文

- **触发：** 同时传入 `send <ticket> --merge-tip --file <handoff.md>`。
- **观察：** P3 所用 `cmdSend` 优先选择 merge-tip 分支，文件正文被忽略。共享接口说明可能没有进入执行者会话。
- **已用绕行：** 单独 `send <ticket> --file <handoff.md>`，在文件内写准确的 `git merge <已接受提交>` 命令和完整交接；随后核对实际生成的消息包含正文。活动回合结束后再发送，避免重复派发。
- **建议结果：** 两参数明确组合，或在不支持时显式拒绝；新增参数组合测试应验证实际发送内容。
- **证据：** P3 档案 `evidence/03-merge-02-dispatch-5b894b0b.json`、`messages/03-merge-02-5b894b0b.md`；[脱敏摘录](pitfalls/evidence/os-p3-project-foundation/checks.md#交接正文与审查分类)。

## WL-04 审查依据解析后的范围误分类

- **触发：** P3 #04 初审 Basis 使用 `AC2「…」; floor: Data loss` 等组合格式；P4 #02 以 spec 开头或 AC2 后无冒号，#03 使用全角 `AC2：`。
- **观察：** P3 输入丢失、草稿清除，以及 P4 实际启动选模、恢复和候选资格等验收发现被列为范围外，工具给出可集成提示。该提示与原验收语义不一致。
- **已用处理：** Main 阅读原 AC、报告及复现，裁定范围内返修；产品修复后通过复审。原报告和工具标签保留，无 override 或 waiver。后续简报采用 ASCII `AC2:` 并核对解析结果。
- **建议结果：** 对不可解析的 Basis 明确报出需核对的字段，保留原发现；解析失败不直接等同于范围外。规则修改需用原报告样例验证。
- **证据：** P3 档案 `reviews/04-7b8bc726.md`、`evidence/04-review-7b8bc726/main-adjudication/`、`reviews/04-dd3a330e.md`；P4 档案 `messages/02-rework-0c5b4ed6.md`、`messages/03-rework-b3703767.md` 和 [解析摘录](pitfalls/evidence/os-p4-native-development/checks.md#审查解析与同版本恢复)。

## WL-05 共享验收准备回执

P3 四段固定候选验收分别重复 setup/verify，早期手工打包与正式打包也有重复。建议评估能否在同源码、依赖和环境下引用一次准备回执，每段保留自身命令、退出码和漂移检查；相关输入改变时使引用失效。是否需要工具支持尚未决定，项目已有 [证据复用规则](development-handoffs.md#输出失败与复用)。来源：P3 档案 `evidence/06-a1/acceptance/` 和 [复盘 §8](p3-retrospective.md#8-减少脚手架试错和重复准备)。

P4 提供了两类已采用样例：同 tip 终审仅补报告格式时复用原命令回执；stdin 补修后以源码差异对应旧 full/UI/数据库记录，以新包补命令验证。通用支持可保留候选、依赖、环境和输入身份及复用理由，按实际变化使相关证据失效。来源：[P4 候选与包身份](pitfalls/evidence/os-p4-native-development/checks.md#候选与包身份)。

## WL-06 诊断脚本的失败表达

P3 #04 的真实子进程 probe 打印了恢复超额/重复执行现象，但进程 exit 0，未满足复审边界要求的明确失败命令。后来独立审查在精确旧提交 `4d90cf6` 加新测试得到 exit 1，在修复候选上通过。原 probe、后续测试和审计 narrowing 提示分别保留。

建议诊断脚本用断言把违例变成非零退出，报告写清失败基线和条件。此项归证据表达质量；没有确认 Workloop 的失败判定实现存在缺陷。证据为 P3 档案 `evidence/04-review-4d90cf63/restart-bind-race-output.log`、`evidence/04-review-dd3a330e/red-atomic-reclaim-on-4d90cf6.tap`，以及 [原复盘说明](p3-retrospective.md#5-恢复回收必须复核锁内状态)。

P4 另有探针返回契约、权限和输出断言构造错误；原失败与校正回执均保留在 [复盘 §7](p4-retrospective.md#7-失败逐项归因复用按源码和输入判断)。红复现若按预期观察缺陷后 exit 0，报告需明确红复现目标、实际观察和产品断言结果。这些构造问题归入证据质量，不单列为工具缺陷。

## WL-07 跨运行审计

科学剪枝结束时提示 7 个 run，P3 为 8 个，P4 收尾时提示自 2026-11-05 上次横向检查后已有 9 个 run 完成。建议由未编排这些运行的独立审查者比较重复失败、实际返修、依赖准备和采样成本。当前已完成各轮复盘及项目文档整理；未执行跨轮审计，未更新其基线。

## WL-08 最终报告格式反馈

- **触发：** P4 最终审查用 `## Verdict` 标题和 `**pass**` 表达通过。
- **观察：** 同提交 15 条命令、56 tests 通过且零漂移，工具返回 verdict missing；有效机器字段要求未满足。
- **已用处理：** 另存原件，第二轮在同 `762ecb8d` 核对原始回执，补 `Verdict: pass` 与完整 `Integration tip:`，复用已完成检查。没有源码返修或 waiver。
- **建议结果：** 报告完成时即检查必需字段并定位格式错误；是否兼容 Markdown 另行决定。需保留原报告及核对过程。
- **证据：** P4 档案 `evidence/final-1-verdict-format-reconciliation.json`、`reviews/final-2-762ecb8d.md`，以及 [脱敏摘录](pitfalls/evidence/os-p4-native-development/checks.md#审查解析与同版本恢复)。

## WL-09 归档数据所有权

P4 归档时，scratch 与执行工作树内仍有用户已配置的 UI、凭据及交付样例。Main 核对归属和空闲状态，保全到私有目录并恢复兼容入口，归档后验证服务与数据。项目侧已记录 [操作坑点](pitfalls/testing.md#归档目录内仍有用户配置的实例)。

建议工具支持保留路径清单、删除集合与占用的预检，以及明确的所有权交接；带用户配置的实例可直接放到独立持久目录。此项为能力建议，未修改 archive 行为。原凭据不进入证据或建议附件。来源：P4 档案 `evidence/main-runtime-relocation.json`、`evidence/archive-verification.json`。

## WL-10 每轮报告身份与建议视图

P4 #06 同候选复审沿用报告路径，审计读到 11 个票级报告，而事件有 12 次 review；旧版本已另存。导出的 89 条建议还包含重复项、后续已修复观察及元数据。

建议每轮审查使用不可变报告 ID，计数区分事件、文件和有效 verdict；建议视图按来源归并并关联已修复、待确认、范围外等状态，同时保留原文。当前项目文档仅按主题整理，工具记录格式与计数未改。来源：[P4 保全与审计摘录](pitfalls/evidence/os-p4-native-development/checks.md#保全与审计)。

原建议与原始日志继续保留。新一轮工具工作应按所选问题确定范围和完成标准，不把历史建议数量直接当作待修缺陷数。
