## WL-01 provider 替换与返修计数

科学剪枝发生过一次 README 返修和 Terra → DSH 替换，工具机械 rework 为 0。建议同时呈现替换原因、前轮 verdict、实际返修与工具计数，避免用替换或 retry 隐去返修。当前交接可按 [替换执行者](development-handoffs.md#替换执行者与归档) 记录；工具计数改动另行评估。来源：[科学剪枝复盘](core-pruning-retrospective.md)。

## WL-02 返修简报中的验证责任

科学剪枝的窄文案返修仍引发重复检查。建议通用简报列出本轮增量、执行者检查、独立审查及集成/finish 必需门禁。项目侧已有 [交接表](development-handoffs.md#派发与返修)，通用模板尚未修改。来源：科学剪枝复盘与 [P3 重复准备](p3-retrospective.md#8-减少脚手架试错和重复准备)。

## WL-03 组合参数忽略交接正文

- **触发：** 同时传入 `send <ticket> --merge-tip --file <handoff.md>`。
- **观察：** P3 所用 `cmdSend` 优先选择 merge-tip 分支，文件正文被忽略。共享接口说明可能没有进入执行者会话。
- **已用绕行：** 单独 `send <ticket> --file <handoff.md>`，在文件内写准确的 `git merge <已接受提交>` 命令和完整交接；随后核对实际生成的消息包含正文。活动回合结束后再发送，避免重复派发。
- **建议结果：** 两参数明确组合，或在不支持时显式拒绝；新增参数组合测试应验证实际发送内容。
- **证据：** P3 档案 `evidence/03-merge-02-dispatch-5b894b0b.json`、`messages/03-merge-02-5b894b0b.md`；[脱敏摘录](pitfalls/evidence/os-p3-project-foundation/checks.md#交接正文与审查分类)。

## WL-04 审查依据解析后的范围误分类

- **触发：** P3 #04 初审 Basis 使用 `AC2「…」; floor: Data loss` 等组合格式。
- **观察：** 工具把两项实际涉及输入丢失、草稿清除的发现列为范围外，给出可集成提示。该提示与原验收语义不一致。
- **已用处理：** Main 阅读原 AC、报告及复现，裁定范围内返修；产品 P1/P2 后来通过复审。原报告和工具标签保留，无 override 或 waiver。
- **建议结果：** 对不可解析的 Basis 明确报出需核对的字段，保留原发现；解析失败不直接等同于范围外。规则修改需用原报告样例验证。
- **证据：** P3 档案 `reviews/04-7b8bc726.md`、`evidence/04-review-7b8bc726/main-adjudication/`、`reviews/04-dd3a330e.md`。

## WL-05 共享验收准备回执

P3 四段固定候选验收分别重复 setup/verify，早期手工打包与正式打包也有重复。建议评估能否在同源码、依赖和环境下引用一次准备回执，每段保留自身命令、退出码和漂移检查；相关输入改变时使引用失效。是否需要工具支持尚未决定，项目已有 [证据复用规则](development-handoffs.md#输出失败与复用)。来源：P3 档案 `evidence/06-a1/acceptance/` 和 [复盘 §8](p3-retrospective.md#8-减少脚手架试错和重复准备)。

## WL-06 诊断脚本的失败表达

P3 #04 的真实子进程 probe 打印了恢复超额/重复执行现象，但进程 exit 0，未满足复审边界要求的明确失败命令。后来独立审查在精确旧提交 `4d90cf6` 加新测试得到 exit 1，在修复候选上通过。原 probe、后续测试和审计 narrowing 提示分别保留。

建议诊断脚本用断言把违例变成非零退出，报告写清失败基线和条件。此项归证据表达质量；没有确认 Workloop 的失败判定实现存在缺陷。证据为 P3 档案 `evidence/04-review-4d90cf63/restart-bind-race-output.log`、`evidence/04-review-dd3a330e/red-atomic-reclaim-on-4d90cf6.tap`，以及 [原复盘说明](p3-retrospective.md#5-恢复回收必须复核锁内状态)。
