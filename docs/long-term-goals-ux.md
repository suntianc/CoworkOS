# 长期任务的交互组织

持久状态和控制语义见 [目标架构](long-term-goals-architecture.md)，使用入口见 [运行时参考](runtime-reference.md#长期目标接口与调度)。

按[阶段规划](development-phases.md)，P4.5 移除长期任务与监控的界面入口，只保留后端能力与接口；本页描述的交互在移除前有效，产品中的使用方式日后单独规划。

## 页面与信息层级

| 入口                      | 默认内容                                             | 进一步查看                       |
| ------------------------- | ---------------------------------------------------- | -------------------------------- |
| 长期任务 → 目标           | 名称、一句最新进展、自然语言状态；需要处理的目标优先 | 点卡片查看一个目标               |
| 长期任务 → 动态；侧栏铃铛 | 重要结果、周报和决策，按时间排序，支持未读筛选与分页 | 来源链接、查看所属目标、标为已读 |
| 目标 → 进展               | 待回答问题优先，其后是最新进展、接下来、近期动态     | 长报告按需展开                   |
| 目标 → 计划               | 计划步骤与状态、已确认事实                           | 展开步骤依据                     |
| 目标 → 设置               | 原始要求、汇报方式、偏好、完成标准、来源状态         | 来源设置与检查记录               |
| 目标 → 全部动态           | 完整动态和较早记录                                   | 内部记录单独展开                 |

暂停目标收进可展开分组，已结束目标进入单独列表。首页不展示采样次数、模型次数、脚本、原始日志和完整事实列表。默认仅提醒重要结果；普通记录是否逐条提醒由汇报策略决定。源故障、模型未连接、调度关闭、等待规划与等待用户分别呈现，不能用“正在工作”覆盖实际停止状态。旧监控的暂停/结束状态在列表和详情中保持一致。

长期任务使用普通页面，保留应用侧栏；不会用大弹窗遮住整个工作区。只有编辑简报和最近会话等短操作使用弹窗。侧栏铃铛与长期任务的“动态”指向同一页面；最近会话另保留轻量入口，默认不混入后台监控会话。

## 创建与控制

创建以一段自然语言描述为主，名称可自动产生；示例只帮助填写，不会在未提交时创建任务。跟进位置和汇报偏好直接可选，命名、完成标准及其他偏好留在“更多要求”。失败保留草稿和创建请求标识，重试不会另建重复目标。

暂停/恢复在目标页直接操作；修改要求和结束目标放进更多菜单。结束前明确显示其效果并要求一次确认，已有结果保留。原对话始终可打开继续沟通，返回对话不覆盖原输入草稿。

## 导航、状态与刷新

- `#goals`：目标总览；`#goals/activity`：动态；`#goals/:taskId/:programId/:tab`：目标详情。刷新保留正在查看的目标与标签。
- 返回所有目标、应用后退、侧栏选择对话和返回对话有一致的退出路径。页面不锁定键盘焦点，编辑弹窗保留焦点管理；详情标签支持方向键。
- 未提交的回答按目标及问题标识缓存在当前页面，切换计划/设置后仍保留。成功提交后走原有持久答案链路，并确认对应提醒已读。
- 页面切换及写操作使旧请求失效。慢响应不能替换另一个目标，写入前发出的旧轮询不能把暂停后的界面改回运行中。
- 同一次页面状态下合并在途读取，合并聊天流引起的刷新；轮询只读取状态，不触发模型。隐藏页面不轮询。

## 代码边界与验收

`goal-controller` 管理页面、路由、读写与并发；`goal-view` 负责展示模型；`goal-form` 负责简报编辑。后端新增只读的分页动态接口 `/api/goals/activity`，继续复用目标记录、通知与已读状态，没有新增模型预算或调度体系。

界面验收包括目标/动态分开、待决策优先、跨目标分页和未读、来源证据、长报告展开、失败草稿、深链接刷新、返回原对话、窄屏、键盘、旧响应竞争、已暂停旧监控的列表/详情一致。验收截图使用隔离测试数据，不代表真实新闻或正式监控结果。
