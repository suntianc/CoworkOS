## Directory map

```text
scripts/install.sh         CLI installation: published release, verification, user prefix and PATH
scripts/atria.mjs          User CLI launcher: init, doctor, start, etc.
src/cli/                  Executable entrypoints, the CLI host backend and its worker
src/domain/               Task, Run, Experiment types
src/runtime/              Pi processes, delegation, recovery, inbox, supervision
src/tools/                Files, commands/jobs, Web and other runtime tools
src/workspace/            Task workspaces, inputs, artifacts, projects and global catalogs
src/storage/              JSONL events and file locks
src/dashboard/            Local HTTP/SSE, routes, composition, Main process lifetime
src/gui/ + src/security/  Computer Use, native drivers and execution grants
.pi/extensions/           Thin Pi entry
.pi/runtime/              Pi lifecycle composition, domain tools
.pi/skills/               Product skills and reference materials
web/                      Native ES modules: composition, controllers, domain UI
desktop/                  Electron main, trusted preload, encrypted settings, exit saving
test/                     Node behavior/protocol/lifecycle; compiled p0/p1/p2 tests
e2e/                      Chromium and isolated Electron user flows
scripts/                  Builds, packages, dev launchers, tests and documentation gates
docs/                     User guides, development conventions and API references
```

The [CLI installer](../../scripts/install.sh) uses the public update feed, verified release archives and a user prefix. Run `node --test test/install.test.js` for its [installation and rejection tests](../../test/install.test.js).

Reusable HTTP behavior does not belong in `src/cli/`. HTTP helpers live under `src/dashboard/`. Build outputs are `dist/`, `build/`, domain UI `generated/` and `.tmp/`; edit source and rebuild. Desktop icons in `build/` are generated by the [icon build script](../../scripts/build-desktop-icon.mjs) from the [source mark](../../web/assets/atria-symbol.png) and [Swift renderer](../../scripts/render-desktop-icon.swift). Development apps and packages consume them; do not maintain or commit generated copies.

The [entry controller](../../web/assets/controllers/entry-controller.js) owns the work/observation entry state: the active entry, the observation view and their restoration after a reload. Elements marked `data-entry-panel`, `data-entry-mode` and `data-observe-view` in `web/index.html` are the mount points later tickets fill. Verify the [controller regression](../../test/p45-entry-shell.test.js) and the [browser switch](../../e2e/p45-entry-shell.spec.js).

The [observation data port](../../web/assets/controllers/observe-data.js) supplies the read-only view data: one session, catalog snapshot and event stream per connected node, aggregated by node for projects, requirement counts and running work. ## Three common change recipes

### Fix a user flow

Start from its reproduction/e2e/protocol test and trace requests/events to the state owner. Fix semantics there; routes map fields/status and UI handles presentation/interaction. Add a regression that reproduces the original failure, run related tests and verify, then corresponding browser tests for UI changes.

### Add a tool

Define inputs, outputs, cancellation and failure guarantees first, then implement the tool under `.pi/runtime/tools/` or `src/tools/` and expose it through an `enable_tools` group. HTTP, agents and the UI share one operation implementation. Add a real-Pi regression and the matching documentation. Attachments and delivery keep using `read_attachment` and `publish_artifact`; do not add a second delivery protocol.

### Split a large module

Identify state transitions, persistence, process ownership and rendering. Keep exports/formats/entrypoints compatible and migrate one responsibility with all consumers. Extracted modules cannot import their composition layer. Use architecture regression and existing behavior tests. Verify dependency direction and recovery behavior.

Review roles are in [module ownership](../module-ownership.md) (Chinese). This page gives navigation; root/scoped AGENTS provide constraints.

App/Web interface language is owned by the [literal translator](../../web/assets/ui/language.js), [English catalog](../../web/assets/ui/language-en.js) and [settings controller](../../web/assets/controllers/language-settings.js). Only source literals are translated; interpolated user content is untouched and no DOM observer is installed. Static shell text is translated once before rendering user content; the English catalog loads only for English sessions. Switching reuses the document/draft close gate in `web/app.js` before reloading. [Desktop language preferences](../../desktop/language.cjs) persist independently through trusted main-window IPC.
