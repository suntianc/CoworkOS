# Electron 宿主

桌面拥有窗口、可信 IPC、加密配置、数据目录与本地后端。业务服务和共用 UI 分别在 `src/` 与 `web/`，不要在桌面复制一套。

- 原生能力只接受可信主窗口的主 frame；产出物预览窗口不暴露 preload/Node。新增 IPC 必须做发送方与参数验证。业务数据走与浏览器相同的 HTTP 协议，IPC 只承担窗口、通知、文件选择、凭据与草稿等宿主能力。
- 本地后端是独立的执行主机：桌面经 `dist/src/cli/backend.js` 的实例归属启动或复用它，同一数据根只有一份实例记录和一个写入服务。`backend start`、`npm run ui` 与桌面重复启动时复用或明确拒绝，不另起端口。
- 后端启动使用就绪通知、随机端口与会话 token，不依赖固定端口或延时猜测。桌面的宿主凭据来自实例记录，只进入 httpOnly 会话 cookie，不进入 renderer 状态和安装包。
- 密钥只由宿主读取/保存，不进入 renderer 状态和安装包。
- 退出先等待文档与草稿保存，再关闭 Run 进程组与 MCP；后端继续运行，已接受的任务不被退出中断，下次打开连接同一实例。保存失败要保留可恢复状态。只有用户显式更换设置或安装更新才停止后端，并随后重新连接。
- 窗口访问（Computer Use）的授权由执行主机提供；桌面不再通过子进程 IPC 转交。连接到尚未提供该接口的后端时，读取已保存策略仍可用，授权操作要返回明确错误。
- 用户数据与安装资源分开，升级不覆盖用户配置。开发与已安装应用路径都要验证。

运行 `test/desktop-*.test.js` 与 `test/electron-connect.test.js` 对应回归；窗口、退出和打包变更还需 [Mac 发布](../docs/mac-release.md) 的原生 smoke。记录锁屏、权限、平台跳过，不能等同通过。
